# WS-B: Content pipeline test cases

Scope: `npm run seed` (validation, idempotent upsert, archive semantics), `npm run db:reset:test` fixtures and variants, `npm run exercises:verify`, `npm run content:stale`, and the §6 RLS contract (anon key read-only).
Owned paths: `scripts/seed/`, `scripts/exercises/`, `supabase/seed/`, `tests/fixtures/`. The browser-facing E2E for S-3.1 lives in [ws-m2-integration.md](ws-m2-integration.md); rendering of seeded markdown lives in [ws-c-curriculum-lesson.md](ws-c-curriculum-lesson.md).
Contract: [README.md](README.md) (case format, fixtures, AC IDs, AMB-nn).

**Shared helpers for this file** (proposed, in `tests/helpers/`):

| Helper | What |
|---|---|
| `contentSandbox(fixtureName)` | Copies `tests/fixtures/content/<fixtureName>/` (a mini `content/` + `exercises/` tree) into a temp dir and returns its path. Seed is pointed at it with `CONTENT_DIR` and `EXERCISES_DIR` (AMB-B1). |
| `runSeed(dir)` | Spawns `npm run seed` with the sandbox env; resolves `{ code, stdout, stderr }`. |
| `dumpTables()` | Service-role read of `levels`, `lessons`, `exercises`, `news_sources` with **every column**, ordered by `slug`, serialised to stable JSON. Used for byte-identical comparisons. |
| `anonClient()` / `serviceClient()` | Supabase clients built from the local anon key and the service-role key in `.env.local`. |
| `content-valid` | Sandbox fixture: 2 levels, 4 lessons, 2 exercises, mirroring the `fx-base` curriculum (README §3.1) as repo files. |

All integration cases start from `supabase start` plus `npm run db:reset:test -- --variant=fx-no-content` unless stated otherwise, so the seed writes into empty tables.

## Suite B1: Content structure and happy-path seed

### TC-B-01: Seed loads a valid content tree
- **ACs:** S-1.1, S-1.2
- **Level:** integration
- **Priority:** P0
- **Category:** Happy
- **Preconditions / fixtures:** `fx-no-content`; `contentSandbox('content-valid')`.
- **Steps:**
  1. `runSeed(dir)`.
  2. `dumpTables()`.
- **Expected:** exit code 0. `levels` has 2 rows (`l1`, `l2`) with `number`, `title`, `summary`, `sort` from `content/levels.yaml`. `lessons` has 4 rows whose `slug`, `level_id`, `sort`, `title`, `objective`, `est_minutes`, `tool_versions`, `last_verified_on`, `differences` equal the frontmatter values, and whose `concept_md`, `claude_md`, `codex_md` equal the text under `## Concept`, `## Claude Code`, `## Codex CLI` (headings excluded, trimmed). `exercises` has 2 rows linked to the lesson named by the frontmatter `exercise` slug. All `archived_at` are null. All `id` values match the UUID v4 regex and were generated by Postgres (the seed never sends an `id`).

### TC-B-06: Unicode, BOM and CRLF content is normalised identically
